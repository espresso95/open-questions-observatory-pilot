# Pilot boundaries

The exact question, fixed protocol and limited literature coverage are in `config/`. No answer to the bounded comparison was found in that search. This is not an independent novelty assessment or proof that no answer exists anywhere.

The forecast methods are established. A small experiment using recent observations may be useful without inventing a new algorithm. The physical spring predictability barrier remains open, regardless of the pilot's outcome.

Source reading and question formulation are agent-assisted. The software automates retrieval, evidence matching, hashes, bounded execution, reproduction and export. It does not claim autonomous multidisciplinary discovery or continuous monitoring.

Rights, exact source evidence and input hashes are checked before execution. The broker allows only exact configured public HTTPS URLs and does not follow redirects. Generated research runs in a dedicated Linux VM, with no host-directory mounts, credentials or network. Python virtual environments are used for host verification only, not as the research isolation boundary.

The experiment plan is internally frozen before outcomes are generated. It is not externally preregistered. Changes to the analysis create a different plan identity. Existing results, failures and plan versions stay in private state. An idempotent rerun reuses the completed run rather than silently testing another variant.

Only the non-sensitive government data snapshot, short source evidence, metadata, results and reproducibility files enter the review bundle. Full source-paper HTML and local SQLite never enter the site. Data and source-paper rights remain separate from project-owned code and report licensing.

Scientific review, reproduction and disclosure approval are separate. No model-generated output can become external peer review. No public GitHub PR, push or deployment is allowed until a human approves the current bundle digest, as required by design section 12. A changed bundle invalidates approval.

The pilot has no installed recurring job, public API, paid inference, email outreach, contribution executor, production daemon or seven-day reliability qualification. Those are later milestones. A local one-shot path cannot establish production readiness.
